The main bottleneck in the age of AI coding is the pull request

By: Zakhar Garan · 24 November 2026 · First published on LinkedIn

AI has learned to write code in minutes, and now teams have run into a different problem: there is no one to read it. When the pull request queue grows faster than engineers can work through it, review turns into a formality. People simply stop reading huge PRs carefully.

In its new playbook, Anthropic pointed out the obvious: if an agent generates the code, an agent should also do the first review. In this model, review works both ways.

A separate agent with a clean context takes over the routine: it looks for logic errors and checks edge cases, security and compliance with the repo's rules. If another agent wrote the code, that agent can make the fixes itself and update the branch before the notification even reaches the engineer. One strict rule applies: an agent never approves its own work and cannot merge code to production on its own.

As a result, the engineer no longer hunts for small bugs. Their focus moves to where machines are still helpless: assessing architectural risks and making sure the solution does exactly what the business needs.

I wonder whether anyone has already set up a pipeline like this, or are you all still going through AI assistants' diffs by hand?
